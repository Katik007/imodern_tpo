# ДЗ №2 · UI-автотесты iModern

## Объект тестирования

Публичный интернет-магазин мебели iModern. Авторизация проверяется через защищённую страницу профиля. Для сценария покупки выбран кремовый стул Blanca, код товара 129033. Тест сравнивает текущую цену в карточке и корзине, поэтому временные изменения цены сами по себе не ломают проверку. [Профиль](https://imodern.ru/personal/profile/) · [Карточка стула](https://imodern.ru/product/stul-blanca-kremovyy/)

Из первого ДЗ адаптированы проверки корректного входа, обработки пустых полей, неизвестного аккаунта и неверного пароля, а также критический путь через карточку, корзину и оформление. Поле авторизации iModern подписано «E-mail». Номер из профиля с правильным паролем в этом поле отклоняется.

## Запуск

Дважды нажмите `run_tests.cmd`. Скрипт устанавливает зависимости, запускает Chromium и тесты, затем открывает Allure. Для первого запуска на Windows нужны Python 3.10+, Java 8+ и интернет. Настройки и реквизиты тестового аккаунта читаются из локального `.env`. [Инструкция](ИНСТРУКЦИЯ.md)

## Сценарии

| ID | Проверка | Ожидаемый результат |
|---|---|---|
| AUTH-01 | Вход по email с правильным паролем | Открывается профиль нужного пользователя. Сверяются имя и email, а при наличии номера в настройках и телефон |
| AUTH-02 | Пустой email | Браузер выделяет обязательное поле. Форма входа остаётся на экране |
| AUTH-03 | Пустой пароль | Браузер выделяет поле пароля. Форма входа остаётся на экране |
| AUTH-04 | Некорректный формат email | Появляется «Неверный логин или пароль». Профиль недоступен |
| AUTH-05 | Несуществующий email | Появляется «Неверный логин или пароль». Профиль недоступен |
| AUTH-06 | Существующий email и неверный пароль | Появляется «Неверный логин или пароль». Профиль недоступен |
| AUTH-07 | Телефон из профиля вместо email с правильным паролем | Появляется «Неверный логин или пароль». Профиль недоступен |
| AUTH-08 | Подсказка о формате email | Ожидается пояснение о формате. iModern показывает общую ошибку «Неверный логин или пароль», поэтому проверка падает |
| SHOP-01 | Поиск Blanca, карточка, корзина и первый экран оформления | Найдена ожидаемая модель. Проверены вариант, цена, количество, итог корзины и поля контактов на первом экране |
| E2E-01 | Отправка формы и подтверждение созданного заказа | Пропуск в публичном прогоне. Отправка передаёт заявку продавцу и запускает обработку реального заказа |

Для покупки используется гостевая сессия с пустой корзиной. На проверенном экране оформления CAPTCHA не обнаружилась. Рядом с кнопкой «Продолжить оформление» сайт сообщает о принятии оферты. Полный E2E до номера заказа требует согласованной с iModern тестовой среды. [Условия оформления заказа](https://imodern.ru/dogovor-oferta/)

## Код и отчёт

| Часть | Назначение |
|---|---|
| `core/` | Конфигурация, браузерные контексты, логирование, Allure и публикация результатов |
| `ui/` | Page Object и BaseElement, локаторы CSS, ожидания Playwright |
| `autotest/` | Сценарии, фикстуры и диагностика |
| `data/` | Параметры авторизации и данные товара |

Python-пакеты зафиксированы в `requirements.txt`. Allure CLI 2.34.1 указан в `core/allure_cli.py`. Скриншоты при ошибках маскируют поля ввода и известные личные данные. В Allure используются категории входных данных и шаги без реквизитов аккаунта. Логи пишутся в `logs/autotest.log`.

| Файл | Содержимое |
|---|---|
| `allure-report/index.html` | Шаги, статусы, скриншоты и причины пропуска |
| `test-results/summary.md` | Итог последнего прогона по каждому ID |
| `test-results/pytest.xml` | Машиночитаемые результаты JUnit |

Эти файлы создаются при локальном запуске. Для сдачи готовый отчёт Allure можно открыть из отдельного HTML-файла в браузере.
